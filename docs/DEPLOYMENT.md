# Технічний супровід

Цей документ призначений для супроводу коду. Користувацький опис і правила роботи застосунку містяться в кореневому [README](../README.md).

## Архітектура

- `public/` — статичний адаптивний PWA-клієнт, який публікується на Vercel.
- `public/config.js` — спільна адреса API Worker; значення публічне, секрети сюди не додають.
- `worker/index.js` — Cloudflare Worker API: читання публічного Telegram preview, адаптери офіційних графіків, OCR для Сумщини, CORS і KV-кеш.
- `wrangler.jsonc` — конфігурація production Worker для Cloudflare Workers Builds із кореня репозиторію.
- `worker/wrangler.toml` — конфігурація для локальної розробки та окремого запуску Wrangler із `worker/`.
- `worker/index.test.js` — модульні тести парсера й API на вбудованому Node.js test runner.

Worker приймає ім'я або посилання на публічний Telegram-канал, а також лише внутрішньо allowlist-нуті адреси офіційних фідів. Він аналізує до п'яти останніх дописів, читає структуровані графіки ДнЕМ/ЦЕК через YASNO та Черкасиобленерго через його публічний JSON/HTML API. Для офіційного Telegram-каналу Сумиобленерго Worker завантажує графік-зображення, викликає OCR.space Engine 3 у режимі таблиці й показує результат лише після перевірки всіх 12 підчерг. Доступність джерела не означає загальне покриття всієї області: ДнЕМ і ЦЕК є окремими операторами, а графіки не замінюють аварійні/адресні сповіщення.

Офіційні відповіді та успішні розпізнавання кешуються в KV. Сумський графік кешується за ID допису та SHA-256 зображення; тимчасовий Durable Object lock не допускає одночасного повторного OCR того самого зображення. Якщо всі OCR-провайдери помиляються або результат не проходить перевірку, зображення охолоджується на 15 хвилин і застосунок не показує неперевірений розклад. OCR.space-ключі є необов'язковими Cloudflare Secrets із назвами `OCR_SPACE_API_KEY_1` ... `OCR_SPACE_API_KEY_50` (використовуйте послідовні номери для наявних ключів). Для сумісності старий `OCR_SPACE_API_KEY` приймається як ключ №1, якщо `_1` не заданий. Worker знаходить налаштовані ключі за нумерованими binding-змінними; пропущені номери пропускаються. Для кожного нового зображення початковий ключ чергується, а решта унікальних ключів пробуються по черзі лише якщо попередній завершився помилкою або OCR-текст не пройшов перевірку. Успішне зображення кешується за дописом і хешем картинки, невдалі розпізнавання тимчасово кешуються, а блокування Durable Object запобігає одночасному повторному OCR. Налаштування нумеруються від `_1` до `_50`; 50 — межа, закладена в Worker, і її варто тримати нижче загального ліміту змінних конкретного плану Cloudflare. При переході зі старої назви `OCR_SPACE_API_KEY` можна залишити її як ключ №1 та додавати `_2`, `_3` тощо. Не варто створювати багато акаунтів/ключів для обходу квот: OCR провайдер може застосовувати власні умови та обмеження.

Cron у Wrangler-конфігурації запускається раз на п'ять хвилин для типового Telegram-каналу; інші джерела оновлюються за запитом і кешуються.

## Production

- Вебзастосунок: <https://sho-po-svitlu-ib61.vercel.app/>
- Worker API: <https://sho-po-svitlu-api.k-dinya.workers.dev>
- Основна гілка: `main`.

Репозиторій підключений до Vercel для фронтенду й Cloudflare Workers Builds для API. У Cloudflare Build налаштування мають залишатися на корені репозиторію; deploy command — `npx wrangler deploy`. Wrangler читає кореневий `wrangler.jsonc`, який вказує на `worker/index.js` і KV binding `KV_BINDING`. У Vercel використовується статичний сайт з output directory `public` відповідно до `vercel.json`. Push до `main` запускає автоматичну публікацію.

Адреса Worker, записана у `public/config.js`, публічна й не є ключем доступу. Не зберігайте в публічних файлах токени, секрети або особисті облікові дані.

## Локальна перевірка

Потрібен Node.js 18 або новіший.

```bash
npm test
npm run dev
```

Для локального запуску Worker окремо:

```bash
cd worker
npx wrangler dev
```

Після зміни парсера запустіть `npm test`. Тести використовують локальні приклади й не вимагають Telegram-токена або OCR ключа. Додайте кожен ключ у Cloudflare Worker → Settings → Variables and Secrets → Add → Secret: `OCR_SPACE_API_KEY_1`, `OCR_SPACE_API_KEY_2`, `OCR_SPACE_API_KEY_3` і так далі без пропусків. Значення ключів у код чи чат не додають. Для сумісності зі старою конфігурацією Worker також приймає існуючий секрет `OCR_SPACE_API_KEY`, якщо `OCR_SPACE_API_KEY_1` ще не доданий.
